# EV Charging Intelligence V2.3

## TDX integration
This version adds a server-side/GitHub Actions ingestion layer for TDX EV charging data. TDX credentials are never exposed to the browser.

### 1. Create TDX API credentials
Register at TDX and obtain Client Id / Client Secret. TDX states that member mode uses API keys and OIDC client credentials.

### 2. Add GitHub Secrets
Repository → Settings → Secrets and variables → Actions → New repository secret:
- `TDX_CLIENT_ID`
- `TDX_CLIENT_SECRET`

Optional repository variables:
- `TDX_CITIES`
- `TDX_BASE_URL`
- `TDX_STATIC_WORKERS`

### 3. Workflows
- `update-tdx-static.yml`: every 4 hours. Updates stations / charging_points / connectors.
- `update-tdx-live.yml`: every 5 minutes. Updates live_status.

### 4. Data model
- `data/stations.json` — station master
- `data/charging_points.json` — charger/point master
- `data/connectors.json` — connector master
- `data/live_status.json` — normalized live connector status
- `data/tdx_meta.json` — ingestion metadata and error count

### 5. Frontend
The V2.2 map now consumes the four normalized JSON files. It supports city/operator/search/AC-DC/power/live-status filters and station popups.

### Important
TDX API endpoints and data fields can evolve. The script isolates endpoint paths and field mapping in `scripts/update_tdx.py`. If TDX changes a field, update the normalization functions rather than the frontend.
